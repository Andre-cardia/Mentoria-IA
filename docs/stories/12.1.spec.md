## 1. Overview

Implementar o fluxo completo de recuperação de senha para usuários da plataforma Mentoria IA, utilizando o Supabase Auth nativo (`resetPasswordForEmail` + `updateUser`). O fluxo cobre a solicitação via e-mail, a recepção do link tokenizado e a redefinição da nova senha, respeitando os padrões visuais e de código já estabelecidos na plataforma.

### 1.1 Goals

- FR-1: Permitir que usuários solicitem redefinição de senha via e-mail cadastrado
- FR-2: Enviar e-mail com link tokenizado e expiração clara ao usuário
- FR-3: Permitir que o usuário defina uma nova senha ao acessar o link
- FR-4: Invalidar o token após uso ou expiração
- FR-5: Redirecionar o usuário para o login após redefinição bem-sucedida

### 1.2 Non-Goals

- Autenticação social (Google, GitHub) — fora de escopo
- Recuperação via SMS ou telefone
- Administração de senhas de outros usuários por admins
- Histórico de senhas anteriores (sem reutilização bloqueada)
- Política de força de senha configurável por admin

## 3. Technical Approach

### 3.1 Architecture Overview

Fluxo via Supabase Auth nativo (derivado de CON-1 e decisão técnica @Aria):

```
[LoginPage] ──link──► [ForgotPasswordPage]
                              │
                    supabase.auth.resetPasswordForEmail()
                              │
                     [E-mail com link tokenizado]
                              │
                    [ResetPasswordPage] ◄── token na URL (hash)
                              │
                    supabase.auth.updateUser({ password })
                              │
                    [LoginPage] + mensagem de sucesso
```

O Supabase Auth gerencia: geração do token, envio do e-mail, expiração e invalidação pós-uso. A plataforma gerencia apenas os componentes de UI e a chamada às funções da API.

### 3.2 Component Design

Derivado de FR-1 a FR-8 e planejamento UX (@Uma):

**Novas páginas:**
- `ForgotPasswordPage` — input de e-mail, submit, feedback de confirmação
- `ResetPasswordPage` — inputs de nova senha + confirmação, `PasswordStrengthIndicator`, submit

**Novos componentes:**
- `PasswordStrengthIndicator` — atom que avalia e exibe força da senha em tempo real (NFR-4)

**Modificações:**
- `AuthContext` — adicionar método `resetPassword(email)` e `updatePassword(newPassword)` (FR-8 / CON-5)
- `LoginPage` — adicionar link "Esqueci minha senha" → `/esqueci-senha` (FR-1)
- `plataforma-main.jsx` — registrar rotas `/esqueci-senha` e `/redefinir-senha`

### 3.3 Data Flow

```
ForgotPasswordPage
  → AuthContext.resetPassword(email)
    → supabase.auth.resetPasswordForEmail(email, { redirectTo })
    → Supabase envia e-mail com link
  → UI exibe mensagem ambígua (FR-3)

ResetPasswordPage (acessada via link do e-mail)
  → Supabase detecta hash na URL e restaura sessão temporária via onAuthStateChange
  → AuthContext.updatePassword(newPassword)
    → supabase.auth.updateUser({ password: newPassword })
  → Redirect para /login com estado de sucesso (FR-6)
```

### 6.3 Acceptance Tests (Given-When-Then)

```gherkin
Feature: Recuperação de senha

  Scenario: Usuário solicita reset com e-mail cadastrado (FR-2, FR-3)
    Given o usuário está na LoginPage
    When clica em "Esqueci minha senha"
    Then é redirecionado para /esqueci-senha
    When insere seu e-mail e submete
    Then vê a mensagem "Se este e-mail estiver cadastrado, você receberá um link em breve"
    And não é revelado se o e-mail existe ou não

  Scenario: Usuário redefine senha com link válido (FR-4, FR-5, FR-6)
    Given o usuário acessa /redefinir-senha com token válido na URL
    When insere nova senha e confirmação iguais
    And submete o formulário
    Then a senha é atualizada
    And é redirecionado para /login
    And vê mensagem "Senha redefinida com sucesso. Faça login."

  Scenario: Usuário acessa link com token expirado (FR-7)
    Given o usuário acessa /redefinir-senha com token expirado ou inválido
    Then vê mensagem de erro "Este link expirou ou é inválido"
    And vê opção para reenviar o e-mail de recuperação

  Scenario: Senhas não coincidem (FR-4)
    Given o usuário está em /redefinir-senha com token válido
    When insere senhas diferentes nos dois campos
    Then vê erro inline "As senhas não coincidem" antes de submeter
```

## 7. Risks & Mitigations

| Risco | Probabilidade | Impacto | Mitigação |
|-------|--------------|---------|-----------|
| `redirectTo` não configurado no Supabase Dashboard (CON-3) | Média | Alto — link do e-mail não funciona | Documentar configuração necessária no Supabase Dashboard como pré-requisito |
| Usuário acessa `/redefinir-senha` sem token (link direto) | Baixa | Médio — tela quebrada ou loop | Verificar sessão/hash na URL ao montar `ResetPasswordPage`; redirecionar para `/esqueci-senha` se ausente |
| E-mail vai para spam (limite free tier Supabase) | Média (produção) | Médio | Documentar configuração de SMTP próprio como recomendação pós-deploy |
| `onAuthStateChange` não captura evento `PASSWORD_RECOVERY` | Baixa | Alto — reset não funciona | Testar explicitamente o evento `PASSWORD_RECOVERY` no Supabase Auth |
